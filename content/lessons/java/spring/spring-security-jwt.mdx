## Why this matters

Mobile and SPA clients expect stateless APIs. Spring Security 6 replaces the old `WebSecurityConfigurerAdapter` with a `SecurityFilterChain` bean, integrates OAuth2 Resource Server for JWT validation, and maps scopes or roles to `@PreAuthorize`. Getting issuer, audience, and clock skew wrong produces intermittent 401s that are painful to debug in production.

JWTs are credentials, not sessions: short TTL, refresh via a separate flow, never log full tokens.

## Mental model

Pipeline (simplified):

1. Request hits `Authorization: Bearer` plus a JWT.
2. `BearerTokenAuthenticationFilter` parses and hands off to `JwtAuthenticationProvider`.
3. Validator checks signature (JWKS from issuer), `exp`, `nbf`, optional `aud`.
4. `JwtAuthenticationToken` lands in `SecurityContextHolder`.
5. `@PreAuthorize("hasAuthority('SCOPE_read')")` enforces fine-grained rules.

For first-party login (username/password), issue tokens from your auth service with a signing key or use an identity provider (Cognito, Auth0) and validate the same way.

## Code

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@SpringBootApplication
public class SecurityJwtDemoApplication {

  @Bean
  SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/actuator/health").permitAll()
            .requestMatchers("/api/public/**").permitAll()
            .anyRequest().authenticated())
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));
    return http.build();
  }

  public static void main(String[] args) {
    SpringApplication.run(SecurityJwtDemoApplication.class, args);
  }
}
```

Configure `spring.security.oauth2.resourceserver.jwt.issuer-uri` so Boot pulls JWKS automatically. Pair with [Spring Data JPA](/learn/java/spring/spring-data-jpa) entities only after authorization checks — never trust client-sent user IDs without matching JWT claims.

For service-to-service calls inside a mesh, propagate identity with mTLS or signed service tokens instead of reusing end-user JWTs with inflated scopes. Enable `spring.security.oauth2.resourceserver.jwt.audiences` when your authorization server issues multiple API identifiers.

Expose problem-details JSON (`application/problem+json`) from authentication entry points so mobile clients distinguish expired tokens from wrong audiences without parsing stack traces. Rotate signing keys on the issuer and rely on JWKS caching headers instead of hard-coding individual JWK IDs in every microservice.

Add integration tests with `SecurityMockMvcRequestPostProcessors.jwt()` builders so regressions in authority mapping surface in CI instead of in production 403 storms.

## Common mistakes

- Disabling CSRF globally without understanding cookie-based clients still need protection.
- Storing JWTs in localStorage when XSS risk exists (HttpOnly cookies or BFF patterns are alternatives).
- Using symmetric secrets in multi-service meshes without rotation.
- Mapping every scope manually instead of using `JwtGrantedAuthoritiesConverter` customization once.
