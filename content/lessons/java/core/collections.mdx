## Why this matters

Production services spend most of their CPU cycles moving data between layers. The wrong collection choice shows up as subtle bugs (duplicate keys in a `Set` that should dedupe), latency spikes (`ArrayList.remove(0)` on a queue), or memory bloat (`HashMap` with no initial capacity under load).

The Java Collections Framework gives you interfaces first: code against `List`, `Set`, and `Map`, then swap implementations when profiling says so.

## Mental model

| Need | Interface | Typical implementation |
|------|-----------|------------------------|
| Ordered, indexable, duplicates OK | `List` | `ArrayList` (random access), `LinkedList` (rare today) |
| Unique elements, maybe order | `Set` | `HashSet` (fast), `TreeSet` (sorted), `LinkedHashSet` (insertion order) |
| Key → value | `Map` | `HashMap`, `TreeMap`, `LinkedHashMap` |

`HashMap` and `HashSet` depend on `equals` and `hashCode` on keys (and set elements). If you use mutable objects as keys, never change fields that participate in hash after insert.

Iteration: enhanced `for` uses iterators; `ConcurrentModificationException` means you mutated a collection structurally while iterating (unless you use the iterator’s `remove` or a concurrent variant).

## Code

```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public class CollectionsTour {
  public static void main(String[] args) {
    List<String> queue = new ArrayList<>();
    queue.add("order-1");
    queue.add("order-2");

    Set<String> uniqueCustomerIds = new HashSet<>();
    uniqueCustomerIds.add("cust-a");
    uniqueCustomerIds.add("cust-a");
    System.out.println("unique size: " + uniqueCustomerIds.size());

    Map<String, Integer> stock = new HashMap<>();
    stock.put("sku-widget", 42);
    stock.merge("sku-widget", 3, Integer::sum);

  }
}
```

Use `Map.of` and `List.of` for small immutable snapshots (Java 9+). For Spring Boot APIs, DTO lists are often lists of response objects built from streams over repository rows — the stream collector still lands in an `ArrayList` unless you ask for something else.

When sizing a `HashMap`, set `initialCapacity` if you know approximate entry count to reduce resize churn under load tests. `EnumMap` and `EnumSet` are faster when keys are enums because they skip hashing entirely.

## Common mistakes

- Using `==` instead of `equals` when searching collections of strings or custom types.
- Assuming `HashMap` iteration order is stable across JVM versions (use `LinkedHashMap` if you need predictable order).
- Using a bare `List` without generics in new code (legacy only).
- Calling `subList` and forgetting structural changes to the parent list invalidate the view.
