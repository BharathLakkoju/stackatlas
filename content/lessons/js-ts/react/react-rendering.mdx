## Why this matters

Misplaced `key`s remount children and wipe input focus. Effects that sync derived state fight React's render model. Understanding **render** (compute UI), **commit** (apply DOM), and **reconciliation** (diff) helps you fix performance without random `memo` everywhere.

Closures from the [event loop](/learn/js-ts/internals/event-loop) lesson reappear every render: each function component run creates fresh props/state bindings until hooks persist state across renders.

## Mental model

Calling `setState` schedules a render. React executes your component function, producing a **tree of elements** (lightweight descriptions, not live DOM nodes). It compares the new tree to the previous one:

- Same component type at a position → update props and recurse.
- Different type → unmount old subtree, mount new.
- Lists use **keys** to match identity across reorder; index keys break when items insert or delete.

Side effects belong in `useEffect` (after paint) or event handlers—not in render body. Render must be **pure**: same props/state → same element output.

Concurrent features may interrupt or retry renders; avoid mutating refs that render depends on without clear rules.

## Code

```ts
import { useState, useCallback, type ReactNode } from "react";

type Todo = { id: string; label: string; done: boolean };

function TodoRow(props: {
  todo: Todo;
  onToggle: (id: string) => void;
}): ReactNode {
  const { todo, onToggle } = props;
  return (
    <li>
      <label>
        <input
          type="checkbox"
          checked={todo.done}
          onChange={() => onToggle(todo.id)}
        />
        {todo.label}
      </label>
    </li>
  );
}

function TodoList(): ReactNode {
  const [items, setItems] = useState<Todo[]>([
    { id: "a", label: "Learn reconciliation", done: false },
    { id: "b", label: "Use stable keys", done: false },
  ]);

  const onToggle = useCallback((id: string) => {
    setItems((prev) =>
      prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t))
    );
  }, []);

  return (
    <ul>
      {items.map((todo) => (
        <TodoRow key={todo.id} todo={todo} onToggle={onToggle} />
      ))}
    </ul>
  );
}
```

Stable `key={todo.id}` preserves row identity. Functional `setItems` avoids stale state when updates batch. `useCallback` keeps `onToggle` reference stable when passed to memoized children.

## Common mistakes

- Using array index as `key` when the list reorders or filters.
- Deriving state in render with `useState` + `useEffect` instead of computing during render or `useMemo`.
- Putting subscriptions or fetches directly in render.
- Assuming `React.memo` fixes all perf issues while parent passes inline object literals every render.
