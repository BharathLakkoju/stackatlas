## Why this matters

Teams migrating from Pages Router hit surprises: client hooks in a Server Component file, data that never refreshes because a route was statically cached, or waterfalls from nested async server trees. Next.js 15 and 16 refine **cache defaults** and `fetch` caching—confusing if you do not know what runs on the server versus the browser.

App Router is not "React with folders"; it is a **split runtime** with explicit `"use client"` boundaries.

## Mental model

**File-system routing**: `app/dashboard/page.tsx` is the `/dashboard` UI; `layout.tsx` wraps nested segments and can load data once for children.

**React Server Components (RSC)** execute on the server (or at build). They may `await fetch` and read secrets; they do not use `useState` or browser APIs. **Client Components** hydrate interactivity—mark them with `"use client"` at the top of the file.

**Caching (conceptual)**:

- **Static**: prerendered HTML/RSC payload when possible.
- **Dynamic**: opt in when you need per-request personalization (`cookies()`, `headers()`, `searchParams`, or `export const dynamic = 'force-dynamic'`).
- **Data cache**: `fetch` requests can be cached or revalidated (`next: { revalidate: 60 }` or tags in newer versions); uncached fetches participate in per-request rendering.

Think: server tree assembles UI and streams HTML; client islands hydrate where needed.

## Code

```ts
// app/products/page.tsx — Server Component (default)
type Product = { id: string; name: string; price: number };

async function getProducts(): Promise<Product[]> {
  const res = await fetch("https://api.example.com/products", {
    next: { revalidate: 120 },
  });
  if (!res.ok) {
    throw new Error("Failed to load products");
  }
  return res.json() as Promise<Product[]>;
}

export default async function ProductsPage() {
  const products = await getProducts();
  return (
    <main>
      <h1>Products</h1>
      <ul>
        {products.map((p) => (
          <li key={p.id}>
            {p.name} — ${p.price}
          </li>
        ))}
      </ul>
    </main>
  );
}
```

```ts
"use client";

import { useState, type ReactNode } from "react";

export function AddToCartButton(props: { productId: string }): ReactNode {
  const [pending, setPending] = useState(false);

  async function onClick(): Promise<void> {
    setPending(true);
    try {
      await fetch("/api/cart", {
        method: "POST",
        body: JSON.stringify({ id: props.productId }),
        headers: { "Content-Type": "application/json" },
      });
    } finally {
      setPending(false);
    }
  }

  return (
    <button type="button" onClick={onClick} disabled={pending}>
      {pending ? "Adding…" : "Add to cart"}
    </button>
  );
}
```

Server page fetches with time-based revalidation; client button owns interaction. Split keeps secrets and heavy data on the server while UI stays responsive.

## Common mistakes

- Importing client-only hooks into Server Components without a `"use client"` leaf.
- Expecting `fetch` to always hit the network (cached responses surprise local debugging).
- Giant client bundles because entire subtrees were marked client unnecessarily.
- Ignoring loading and error UI (`loading.tsx`, `error.tsx`) and blocking navigation.
