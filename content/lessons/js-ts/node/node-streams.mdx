## Why this matters

Loading a 2 GB log into a string blows heap on a small container. Piping `fs.createReadStream` through a transform to `res` keeps memory near constant and aligns with how the [event loop](/learn/js-ts/internals/event-loop) schedules I/O callbacks. APIs, CLIs, and ETL jobs that ignore backpressure stall or OOM under bursty traffic.

Node stream types—Readable, Writable, Transform, Duplex—show up in HTTP, gzip, crypto, and database drivers.

## Mental model

A **Readable** produces chunks; a **Writable** consumes them. **`pipe`** wires readable → writable and forwards backpressure: when the writable buffer is full, `readable.pause()` stops pulling until `drain`.

**Transform** streams sit in the middle (parse lines, compress, JSON envelope). Mode matters: flowing mode emits `data` events; paused mode uses `read()`.

Prefer `stream/promises` `pipeline` over bare `pipe` for automatic cleanup on errors. In modern Node, Web Streams interop appears in `fetch` bodies—conceptually similar chunk contracts.

When you attach `data` listeners manually, check `readable.readableFlowing`; switching modes accidentally can buffer unbounded chunks in memory. For HTTP responses, `res.write` returns a boolean—`false` means you should wait for `drain` before writing more, mirroring the same backpressure contract as `pipe`.

## Code

```ts
import { createReadStream, createWriteStream } from "node:fs";
import { Transform } from "node:stream";
import { pipeline } from "node:stream/promises";
import { createGzip } from "node:zlib";

const upperCase = new Transform({
  transform(chunk, encoding, callback) {
    const text = chunk.toString(encoding);
    callback(null, text.toUpperCase());
  },
});

async function copyUppercase(
  inputPath: string,
  outputPath: string
): Promise<void> {
  const source = createReadStream(inputPath, { encoding: "utf8" });
  const destination = createWriteStream(outputPath);
  await pipeline(source, upperCase, destination);
}

async function gzipFile(inputPath: string, outputPath: string): Promise<void> {
  const source = createReadStream(inputPath);
  const gzip = createGzip();
  const destination = createWriteStream(outputPath);
  await pipeline(source, gzip, destination);
}

void copyUppercase("notes.txt", "notes-upper.txt");
void gzipFile("notes.txt", "notes.txt.gz");
```

`pipeline` rejects on any stage error and destroys streams safely. Transforms process chunk-by-chunk instead of one giant string.

## Common mistakes

- Ignoring `drain` when writing manually in a loop to a slow socket.
- Listening to `data` without handling backpressure (readable stays flowing).
- Assuming `pipe` always propagates errors (use `pipeline`).
- Buffering entire HTTP bodies in middleware when `req` could stream.
