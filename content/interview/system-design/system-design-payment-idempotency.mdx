Prevent double charge on retried payment API calls.

## Model answer

Client sends Idempotency-Key; server unique-insert PENDING row before PSP call; duplicate key returns same response body.

Mark CAPTURED/FAILED atomically with ledger row. PSP webhooks idempotent on payment intent id.

Nightly reconciliation vs PSP reports.


## Follow-ups

### Double charge?

Unique key + terminal state blocks second charge.

### Partial failure?

Saga: void auth if capture fails after auth.
