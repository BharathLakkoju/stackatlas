State the equals/hashCode contract and why it matters for HashMap.

## Model answer

If a.equals(b) then a.hashCode()==b.hashCode(). Contrapositive: unequal hash codes imply unequal objects (not converse). Violating breaks hash collections—equal keys unreachable. equals must be reflexive, symmetric, transitive, consistent; compare significant fields. hashCode combines fields used in equals. For subclasses, can break symmetry if not careful—prefer composition or strict class equality. IDE/Lombok generate but review which fields belong—do not include mutable fields that change while in map.


## Follow-ups

### Lombok @EqualsAndHashCode?

Lombok generates both together—exclude fields not in identity.

### Subclass equality?

Subclass equals parent can violate symmetry—use getClass comparison.
