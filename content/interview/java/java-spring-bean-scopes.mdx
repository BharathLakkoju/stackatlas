Explain Spring scopes and a common prototype pitfall.

## Model answer

singleton: one per ApplicationContext—default for stateless services. prototype: new bean per injection or getBean. request/session: web-only lifecycle bound to HTTP scope. Pitfall: injecting prototype into singleton gives one prototype instance created at singleton init unless @Lookup or ObjectProvider refreshes per call. @Configuration classes are CGLIB-proxied so @Bean method intercept calls—singleton semantics inside config. Lazy init delays creation until first use.


## Follow-ups

### Prototype injection into singleton?

`ObjectProvider` or an `@Lookup` method creates a fresh prototype per use.

### @Configuration proxy?

@Bean inter-includes calls so two calls return same singleton unless @Scope prototype on method.
