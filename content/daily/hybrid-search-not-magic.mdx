Pure vector RAG fails in predictable ways: product codes (`SKU-9F2`), rare person names, internal acronyms, and exact error strings (`ENOENT`). Embeddings optimize semantic neighborhood, not token identity.

**Hybrid search** runs at least two retrievers:

1. **Dense** — embedding similarity.
2. **Sparse** — BM25 / inverted index on tokens.

Merge with **reciprocal rank fusion** (robust, no score normalization) or weighted sum after min-max scaling.

```text
query --> embed --> vector top-k
      --> BM25  --> lexical top-k
           \      /
            merge --> rerank (optional) --> LLM
```

Tune on **your** query set: if engineering tickets search by JIRA key, lexical weight goes up. If onboarding FAQs are paraphrased questions, dense weight goes up.

Hybrid does not remove need for **chunking quality** or **evals**—it widens recall so the right passage enters the prompt. Lab: [/labs/rag-chunking](/labs/rag-chunking).
